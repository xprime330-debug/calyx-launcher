# Calyx v0.4 — Centers

## Product scope

Continue the local Android launcher on the v0.3 baseline and implement the next roadmap release: an optional Calyx Notification Center, a practical Control Center, notification badges, an edge Peek Panel, and a Permission Center. All external-system capabilities remain explicit opt-ins; Calyx must never enable sensitive access or change global device state at startup.

## Design direction

**Design movement:** Calyx's own luminous, instrument-panel futurism, borrowing interaction principles (not copied screens or assets) from familiar phone platforms.

**Core principles:** (1) calm at a glance, (2) direct manipulation with clear system-state feedback, (3) privacy before convenience, and (4) platform limits stated honestly.

**Color philosophy:** preserve the selected Calyx style family and accent; notification surfaces use deep ink/glass with a high-contrast accent and semantic amber/red reserved for attention. Controls use the same palette, not a second brand system.

**Layout paradigm:** layered full-width surfaces that unfold from the gesture edge; notification cards form app-grouped vertical streams, while quick controls are large, reachable tiles and sliders.

**Signature elements:** translucent rounded cards with fine hairline borders; a small calibrated status/permission indicator; compact app-colour badges that sit over the icon corner.

**Interaction philosophy:** swipe down on the home surface for Calyx notifications, use an edge swipe or the direct Peek chip, and tap explicit ALERTS/CTRL controls for system actions. When access is unavailable, explain why and offer the system's own shade/settings rather than simulating unavailable powers.

**Animation:** use Android's native dialog and system-panel transitions for these v0.4 surfaces; do not add bounce or custom motion to urgent notifications. Existing launcher motion preferences and system motion settings remain in effect.

**Typography:** Android system sans family throughout; large time/control values use `sans-serif-light`, section labels use `sans-serif-medium` with restrained tracking, and notification content uses readable 14–16sp system text.

**Brand essence:** a privacy-first Android launcher that makes everyday system actions feel composed and personal. Personality: **calm, precise, adaptive**.

**Brand voice:** concise and candid, with permission rationale before action. Examples: “Notification access is optional. Calyx uses it to show your notifications and app badges on this device.” “Android controls this switch; open system settings to finish.”

**Wordmark & logo:** retain the existing Calyx leaf/geometry mark; use the wordmark with a custom spaced “CALYX / CENTERS” lockup in-panel rather than substituting a platform logo.

**Signature brand color:** the Calyx electric ice accent (`#89E5FF`), user-overridable through the existing accent setting.

## Implementation approach

Keep Android's `NotificationListenerService` as the single source of notification state. It updates local active-notification snapshots and package badge counts; the in-app panel calls the listener only after the user grants notification access. Dismissal, snooze, opening and RemoteInput reply are explicit user actions that use the original notification key/action. Notification history is off by default, bounded, device-local, and excluded from portable backups. Per-app mute only hides items inside Calyx and never silences the Android notification itself. Privacy Shield hides notification message bodies in Calyx.

Build the Control Center with supported APIs only: local volume controls, explicit system settings panels for restricted network radios, and opt-in `WRITE_SETTINGS`, notification policy access, and camera access for relevant controls. Clearly show Android-managed/unsupported state. The Permission Center reports access status and launches the appropriate Android settings page only after a user tap.

Implement the Peek Panel as a right/left edge gesture with user-selectable local app favorites and shortcuts to Calyx's own panels. Badges are derived from active notifications and shown on home, dock, recent, and drawer app icons. DND and digest schedules are local, user-configured, inexact daily alarms; DND requires notification-policy access, while digest requires notification access and Android's notification-posting permission on Android 13+.

The v0.3 data model and layout stay compatible; new preferences have safe defaults (history, digest and DND scheduling off; badges and Peek on). Android OS panels remain authoritative and Calyx does not claim to replace the system shade or bypass platform restrictions.

## Project structure

- `app/src/main/java/com/calyx/launcher/MainActivity.kt` — launcher lifecycle, panel entry points, settings, badge refresh and Peek interactions.
- `app/src/main/java/com/calyx/launcher/CentersUi.kt` — notification/control/permission panels, local notes, direct system intents, and the opt-in action handlers.
- `NotificationCenterService.kt` — user-granted Android notification listener, active snapshots, badge state, safe user-triggered actions, local notification history.
- `CenterReceivers.kt` — optional inexact DND/digest schedule receivers and reboot rescheduling.
- `Prefs.kt` — backward-compatible device-local v0.4 preferences; sensitive history stays in a separate non-exported preference store.
- `HomePagerAdapter.kt`, `DrawerAdapter.kt`, `Ui.kt` — notification badge rendering without altering the app identity model.
- `GestureLayout.kt`, `activity_main.xml` — home gestures plus the direct ALERTS, CTRL and PEEK header affordances.
- `AndroidManifest.xml` — optional permission declarations and non-exported components; no access is granted by manifest declarations alone.
- `README.md` — v0.4 feature scope, permission explanations, API/device limitations and build usage.

## Dependencies and platform boundaries

Use the existing Android SDK/API 34 and AndroidX dependencies; no new library is required. The app supports API 26+. Notification access, DND policy access and write-settings access are granted by the user through Android settings. Camera use is requested only when the flashlight control is invoked. Android 10+ does not allow ordinary apps to toggle Wi‑Fi directly, so Calyx opens the system Wi‑Fi controls. The regular Android notification shade remains available everywhere; Calyx's panel is a launcher-only surface.
